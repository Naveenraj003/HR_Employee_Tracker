1.	Document Overview 
 
 
1.1	Purpose 
This Business Requirements Document (BRD) describes the functional and non-functional requirements for the Hospital Employee Tracker – a comprehensive HR and workforce management platform (HF Software) built specifically for hospital and healthcare organisations. The document serves as the authoritative reference for design, development, testing, and stakeholder sign-off. 
 
1.2	Scope 
The system covers the complete employee lifecycle within a hospital environment – from daily attendance tracking and leave management to payroll submissions, profile maintenance, and resignation processing. The platform will be accessible via a secure web-based interface with role-based access controls for employees, managers, and HR administrators.

3.	Business Objectives 
 
The Hospital Employee Tracker is commissioned to achieve the following strategic objectives: 
 
	▪ 	Digitise and centralise all HR operations across the hospital, eliminating paper-based processes. 
	▪ 	Provide real-time attendance visibility and reduce manual payroll errors. 
▪ Empower employees with self-service capabilities – leave applications, document access, and profile updates. 
▪ Ensure full statutory compliance with PF, ESIC, Income Tax (old & new regime), and other labour laws. 
▪ 	Enable managers to make informed decisions through dashboards, visualisations, and approval workflows. 
▪ 	Support organisational transparency through automated celebrations, leave visibility, and holiday management.

5.	Functional Requirements 
 
5.1	Authentication & Security 
The system must support secure, multi-layered access for all user roles. 
 
Req. ID 	Requirement 	Priority 
AUTH-01 	The system shall provide a login page with username/email and password fields. 	High 
AUTH-02 	The system shall support Multi-Factor Authentication (MFA) for all users. 	High 
AUTH-03 	Users shall be able to change passwords from the profile menu. 	High 
AUTH-04 	The system shall provide a secure logout function accessible from the header. 	High 
AUTH-05 	Session timeout shall log the user out automatically after inactivity. 	Medium 
 
5.2	Employee Dashboard 
The dashboard is the default landing screen post-login. It provides a consolidated, real-time view of the employee's key data. 
 
5.2.1	Header Bar 
▪ 	Display employee profile picture (avatar or cartoon), employee code, role, work location, and reporting manager name. 
	▪ 	Show current date, running time, and day of the week. 
	▪ 	Display a notification area showing messages such as 'Payslip Generated' with amount credited. 
	▪ 	Provide a user menu with options: Change Password, MFA Settings, and Logout. 
 
5.2.2	Welcome & Quick-Access Tiles 
The dashboard shall display a personalised welcome greeting followed by up to five configurable quickaccess tiles. A filter mechanism shall allow the employee to choose up to three tiles from the following options: 
 
Tile 	Linked Module 	Description 
Apply Leave 	Leave Request Module 	Shortcut to submit a new leave request 
View Attendance 	Attendance Module 	Quick view of attendance records 
Payment History 	Payroll Module 	Access to past payslips and payment records 
My Documents 	Documents Module 	View nominee and personal documents 
 
 
5.2.3	Attendance Summary Widget 
	▪ 	Display first check-in time and last check-out time for the current day. 
	▪ 	Show total working hours for the current day. 
	▪ 	Provide a check-in / check-out toggle button (on/off method). 
	▪ 	Visualise working days for the past 30 days. 
	▪ 	Show average hours per day and total working hours for the current month. 
 
5.2.4	Leave Overview Widget 
A visual representation (e.g. donut / bar chart) of leave balances must be displayed for the following leave types: 
 
Leave Type 	Display

Sick Leave 	Remaining days

Bereavement Leave 	Remaining days 
Paternity Leave 	Remaining days 
Optional Leave 	Remaining days 
Work From Home (WFH) 	Remaining days 
On Duty (OD) 	Remaining days 
 
5.2.5	Team Leave & Celebrations Widget 
	▪ 	Display team members currently on leave. 
	▪ 	Show upcoming employee birthdays and work anniversaries with employee names visible to all staff. 
▪ 	Display a holiday calendar showing all company holidays for the current year, organised month-wise with dates and descriptions. 
	▪ 	Show recent leave requests submitted by the logged-in employee.

	▪ 	Display a table with: Attendance Date, Shift Code, Shift Name, Start Time, End Time. 
	▪ 	A Shift Change Request button shall allow employees to request a shift modification.

5.4.3	Attendance Regularisation 
Four workflow sections manage regularisation requests:

Approved 	Above + Approved On, Approved By, Approver Remarks

	▪ 	Filter by: Employee Code, Date Range, Status. 
▪ 	Display table: Date, Requested On, Start Time, End Time, Requested Time, Manager Remarks, Status, Action. 
	▪ 	A Search Now button triggers filtered results; Refresh reloads the grid. 
 
5.5	Leave Management 
The leave module (accessible from the dashboard quick-link) handles all leave types with an approval workflow. Leave types managed: Privilege Leave, Sick Leave, Casual Leave, Compensatory Leave, Bereavement Leave, Optional Leave, WFH, Paternity Leave, and On Duty. 
	▪ 	Employees can apply for leave specifying type, dates, reason, and attachment. 
	▪ 	Managers receive a notification and can Approve or Reject with remarks. 
	▪ 	Leave balance is updated automatically after approval. 
	▪ 	Dashboard leave overview widget reflects real-time balances.

6.	Non-Functional Requirements 
 
 
Category 	Requirement 
Performance 	Dashboard and module pages shall load within 3 seconds on a standard broadband connection. 
Security 	All data in transit shall be encrypted using TLS 1.2 or higher. Sensitive fields (Aadhaar, PAN) shall be masked in the UI. 
Availability 	The system shall maintain 99.5% uptime (excluding scheduled maintenance windows). 
Scalability 	The platform shall support concurrent usage by all hospital employees without degradation. 
Accessibility 	The interface shall be responsive and compatible with modern browsers (Chrome, Edge, Firefox, Safari). 
Audit Trail 	All key actions (approvals, rejections, submissions, profile changes) shall be logged with timestamp and user identity. 
Data Retention 	Employee records shall be retained for a minimum of 7 years in line with statutory requirements. 
Localisation 	Date formats shall follow DD-MM-YYYY. Currency shall display in INR (₹). 
 
7.	Assumptions & Constraints 
 
 
7.1	Assumptions 
▪ 	Each hospital employee will have a unique Employee Code assigned by HR prior to system onboarding. 
	▪ 	A single reporting-manager hierarchy exists; multi-level approval chains are out of scope for v1.0. 
▪ 	All statutory identifiers (PAN, Aadhaar, UAN, ESIC, PF) are already captured or will be collected during profile setup. 
▪ Integration with a third-party payroll engine is a Phase 2 initiative; v1.0 covers display and submission only. 
	▪ 	Internet connectivity is available at all workstations used by employees. 
 
7.2	Constraints 
▪ 	The project must comply with the Information Technology Act, 2000 and applicable data protection regulations. 
	▪ 	Biometric hardware integration is out of scope for the initial release. 
	▪ 	Mobile application development is planned for Phase 2; v1.0 is a web-responsive application only. 
	▪ 	Password policies must meet a minimum of 8 characters with complexity requirements.
